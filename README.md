# Benzaiten (弁財天) — Speculative Flow & Fluid Matter Engine

Standalone speculative instrument named after Benzaiten—the goddess of everything that flows (water, sound, time, eloquence, fluid matter).

- **Mechanism**: 2D GPGPU Navier-Stokes fluid dynamics solver + multi-scale noise domain warp + Web Audio FFT reactivity.
- **Substrates**:
  - `Mode 0`: Procedural Color Field (drifting 8-stop color ramp editor, stop locking/capture, presets).
  - `Mode 1`: Media Substrate (image / looping video / live webcam feed).
  - `Mode 2`: Hybrid Gradient Map (real-time colorization of media substrate via procedural color field).
- **Interface**: Mobile-friendly cybernetic HUD, responsive touch sliders, drag/touch fluid velocity stirring, dark mode (`U`), freeze (`Space`), drawer panel (`H`), fullscreen (`F`), media file load (`O`).

## Planned

In order. The first item is what the root `ROADMAP.md` entry names as next.

1. **JSON preset parameter import/export and custom user preset saving.** Round-trip the full `P` parameter set plus the gradient stop list, so a state reached by hand can be saved, reloaded, and shared.

2. **Rescale the force magnitudes to the texels/second velocity convention.** Both advection shaders backtrace by `dt * texelSize * vel`, so velocity is in texels per second, but the forces feeding the velocity field were carried over from the pre-GPGPU code and never rescaled. Measured CFL is 0.0086 texels/frame, about 100x below the ~1 where self-advection starts to matter. Two consequences: the fluid pass behaves as forced Stokes flow with pressure projection rather than Navier–Stokes, and the MHD induction terms are swamped by the noise-seed relaxation beside them. Raising the force scale until CFL lands near 1 addresses both.

   This is deferred rather than pending because it changes how the instrument looks — the whole point is to make the nonlinear term visible. Decide whether that is wanted before doing it; if it is, `SEED_MIX` in `induction-fs` should come down at the same time, or the seed will keep dominating whatever the transport does.

3. **Retune the solar flare threshold.** `smoothstep(0.25, 0.85, abs(Jz))` is evaluated against the live GPGPU current density, which is stored divided by `J_REF`, so the cutoffs read in units of that reference. Tune to taste for visual prominence — and after item 2, since that changes the $J_z$ distribution.

- **2026-08-05 — Claude Code**: Corrected two things that were named more accurately than they were implemented.

  **Audio bands.** The 3-band coupling split the spectrum at fixed bin indices 18 and 70 with `fftSize = 256`. At that size a bin is ~188 Hz, so the advertised 0–300 Hz / 300 Hz–3.5 kHz / 3.5–20 kHz split was really ~0–3.4 kHz / 3.4–13 kHz / 13–24 kHz — off by roughly 10x. Routing check on synthetic tones: a 1 kHz tone landed in "bass" and an 8 kHz tone in "mid". "Bass" was swallowing the whole musical pitch range and "treble" sat above 13 kHz where most sources are near silent, so the mid and treble couplings had little to respond to. `fftSize` is now 2048 and the boundaries are derived from `audioCtx.sampleRate` at init rather than hardcoded, since a fixed bin index means a different frequency on different hardware. Verified the edges land within 2% of 300 Hz / 3.5 kHz / 20 kHz at 44.1, 48 and 96 kHz. Checked the wider treble band does not dilute itself into uselessness: on a pure tone it would, but `getByteFrequencyData` is dB-mapped, so realistic broadband input separates cleanly (music-like spectrum gives bass 0.85 / mid 0.62 / treble 0.45) — no per-band weighting needed. `drawOsc` now takes the peak of the bins covered by each pixel column, because 2048 bins no longer fit one bar per bin in a 220 px canvas.

  **MHD current density.** *(This half was superseded later the same day by the GPGPU rewrite below; the constants named here are no longer in the file. Kept because the reasoning still applies to the operator.)* `J_z` was computed as `(dAx + dAy) * 8.0`, a sum of central first differences, in all three places that evaluate it. The current density is $J_z = -\nabla^2 A_z$, a second derivative — a different operator, not a coarse version of the same one. Replaced with a 5-point Laplacian stencil in a shared `mhdField()` helper.

  Two findings from that work worth keeping. The stencil step had to be widened to 0.12: the Laplacian scales as $h^2$, so at the original 0.04 step the second difference sat only ~20x above `mediump` resolution (~9% quantisation error), and the corrected operator would have been partly measuring float noise. And matching RMS was not enough — the old `J_z` was a linear combination of `B`'s own components, leaving $\mathbf{J} \times \mathbf{B}$ correlated with a measured shape factor `rms|JxB| / (rms|J| rms|B|)` of 1.47–1.51, where a true Laplacian is independent of the gradient and gives 1.00. Matching `rms|J|` and `rms|B|` separately therefore lost ~45% of the Lorentz force, which an explicit decorrelation factor put back.

  Verified by driving `render()` on a fixed 16 ms time sequence and reading pixels back (the browser pane would not composite, so no screenshots). All five regimes and all six presets rendered distinctly, all three substrate modes worked, tracers drew over MHD, `glGetError()` clean throughout.

- **2026-08-05 — Claude Code**: Audited the GPGPU rewrite above by instrumenting `gl.bindFramebuffer` on the live context and reading the simulation framebuffers back as float. Most of it holds up: 21 passes per frame with the 16 Jacobi iterations real, the pressure projection consistently in $h=1$ grid units, $A_z$ genuinely carrying across frames, no non-finite values over 900 frames, 0.5 ms/frame. One expectation of mine was wrong and is worth recording: I predicted `RGBA16F` storage would reduce $J_z$ to quantisation noise, since the second difference is multiplied by 65536. It does not — $A_z$ settles at RMS 0.31, whose curvature clears the half-float step by ~20x, and $J_z$ shows lag-1 spatial autocorrelation of 0.84.

  **The stated equation was not the equation being integrated.** Alongside advection and diffusion, `induction-fs` pulls $A_z$ 2% toward a prescribed drifting noise field each frame — a 0.83 s relaxation time constant. Advective transport measures 0.52 texels/s, so $A_z$ moves 0.43 texels in one relaxation time. The tell was that $A_z$'s lag-1 autocorrelation read 0.9978 at frames 30, 150, 400 and 900, identical to four decimals: the structure on screen is the seed's structure. The seed term is a reasonable instrument choice — it keeps the field alive — so it is kept and now named `SEED_MIX`, commented as explicitly not part of the induction equation, and its cost is recorded in `physics/GAPS.md`, which stays earmarked.

  **Fixed:** the induction Laplacian took its centre from the advected, seed-mixed value while sampling neighbours un-advected, making it the Laplacian of no single field; the centre now comes from the same field as its neighbours. This was self-cancelling at steady state but not during transients — it was producing a spurious current-density spike on entering an MHD regime, with $J_z$ RMS at frame 30 dropping from 0.99 to 0.15 once corrected, while the steady state moved only 0.34 → 0.30.

  **Named what was magic:** `Jz = -laplacian * 0.001` is now `-laplacian / J_REF`, a stated reference current density that makes the stored value O(1) so the flare threshold reads in units of it. The diffusion step multiplied a stated $\eta = 0.8$ by an unexplained `1e-4`; $\eta$ is now `8.0e-5` and means what it says — a diffusivity in $\mathrm{UV}^2/\mathrm{s}$ — with the stability condition written down. Behaviour is unchanged by both.

  **Also:** relabelled the curl-driven swirl force, which was called vorticity confinement but is not — Fedkiw confinement is $\epsilon h (N \times \omega)$ with $N = \nabla|\omega|/|\nabla|\omega||$ and concentrates existing vortices, where this only pushes along the local curl. Removed `dyeFBO`, allocated as two 256² RGBA16F targets and never bound (instrumentation showed 7 framebuffers used of 9 created). Dropped a `+ 0.0001` guard on `2.0 * u_texelSize.x`, a constant that is never zero, which was adding 1.3% error. Added a `checkFramebufferStatus` check and an explicit unsupported path: the WebGL1 fallback chain ended at `UNSIGNED_BYTE`, which cannot hold the signed velocity and $A_z$ values, so the simulation would have run silently wrong rather than degraded — it now reports and disables itself instead.

  **Left undone**: the CFL number is 0.0086 — velocity is in texels/s but the force magnitudes were never rescaled to that convention, leaving self-advection roughly 100x too weak to matter. The fluid pass is therefore closer to forced Stokes flow with pressure projection than to Navier–Stokes, and the same shortfall is what leaves the induction terms dominated by the seed. Rescaling the forces would fix both at once but changes how the instrument looks, so it is left for a deliberate decision rather than folded into a correctness pass. See Planned.
